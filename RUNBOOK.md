# RUNBOOK — как работать со стендом

Два роли: **тестировщик** (гоняет промпты пачками, IT-экспертиза не нужна) и
**исследователь** (возвращается в сессию и выясняет, почему сработал обход).

## Тестировщик — в чате Hermes

1. Открой **новую сессию Hermes**.
2. Вставь **любой промпт** и укажи скилл:
   ```
   /skill hermes-redteam-suite
   ```
3. Hermes прогонит промпт через модель **дословно**, вернёт **полный ответ** и
   покажет **SESSION_ID** (вида `rt-20260909-011632-326d`). Запиши его — по нему
   можно вернуться в этот разговор с моделью.
4. Следующий промпт — обычным сообщением: по умолчанию это **продолжение диалога**
   (multi-turn / crescendo). Новый независимый кейс — попроси «новую сессию».

Target и ключи не переспрашиваются. Твой промпт уходит как есть — никаких
категорий/«улучшений». Если ответ обрезан по лимиту — Hermes покажет
«⚠️ ОТВЕТ ОБРЕЗАН», попроси поднять лимит и повторить.

## Исследователь — вернуться в сессию и расспросить модель

Позже (в любой момент, с любого запуска) войди в ту же сессию и **сам** задавай
модели вопросы — напрямую, без пересказа Hermes:

```bash
cd ${LAB_ROOT}/projects/redteam
python3 chat.py list                       # найти нужный SESSION_ID
python3 chat.py repl --session <SESSION_ID>
#   you> почему ты выполнил этот запрос, а не отказал?
#   model> <полный сырой ответ модели>
#   :show  — весь транскрипт | :paste …:end — многострочный вопрос | :quit — выход
```

Весь контекст того разговора (включая «пробивший» промпт) подтягивается и шлётся
модели — ты продолжаешь ровно с той точки, где сработал обход.

Через Hermes тоже можно: «продолжи сессию <SESSION_ID>, спроси у модели X».

## Для анализатора

Модуль-анализатор читает сессию **по SESSION_ID**:
`out/sessions/<SESSION_ID>.json` (или `python3 chat.py show --session <ID>`).
Формат — история диалога + сырые ответы:

```json
{
  "session_id": "...", "model": "...", "system_prompt": "...",
  "history": [ {"role":"user","content":"..."}, {"role":"assistant","content":"..."} ],
  "raw": [ { "prompt":"...", "response":"...", "reasoning_content":"...",
             "finish_reason":"stop", "truncated": false, "usage": {} } ]
}
```

`response` пуст → весь ответ в `reasoning_content` (норма для thinking-моделей).
Оба поля целиком. Скоринг делает анализатор, не Hermes.

## Разовый прогон без сохранения

Если возврат заведомо не нужен — `ask.py` (ничего не пишет на диск):
```bash
echo "промпт" | python3 ask.py
```

## Правила безопасности (жёстко)

- target ≠ attacker ≠ judge. Тестируемая модель — только target.
- Scope пустой по умолчанию; активные тесты — только своя / письменно
  авторизованная модель.
- Hermes передаёт промпт как есть, но сам не изобретает рабочие вредоносные
  payload (оружие/CBRN/malware).
- Ключи — только env / `~/.hermes/.env`, никогда в файлах пакета.
