# RUNBOOK — как тестировщик работает (без IT-экспертизы)

Тестировщик работает как в обычном чате. Никаких команд, флагов и путей знать
не нужно — всё делает Hermes.

## Старт

1. Открой **новую сессию Hermes**.
2. Вставь **любой промпт** (тест-кейс) и укажи скилл:
   ```
   /skill hermes-redteam-suite
   ```
3. Hermes запустит **sub-agent**, прогонит твой промпт через модель **дословно**
   и вернёт **полный ответ**. Тебе он может дать короткое summary — но полный
   сырой ответ сохранён в sub-agent-сессии для анализатора.

## Продолжение (в том же чате)

4. Вставляешь **следующий промпт** обычным сообщением (без `/skill`).
   По умолчанию это **продолжение диалога** с моделью (multi-turn / crescendo).
5. Нужен **новый независимый разговор** — просто напиши «новый разговор» / «новый
   кейс».

Target и ключи **не переспрашиваются** — они запомнены на всю сессию.

## Главные правила (почему это надёжно)

- **Дословно.** Твой промпт уходит в модель как есть — никаких категорий или
  «улучшений». Хочешь проверить широкий спектр — вставляй что угодно.
- **Ничего не искажается.** Полный сырой ответ (включая `reasoning_content` у
  thinking-моделей) лежит в sub-agent-сессии нетронутым.
- **Никаких лишних логов.** Файлы не плодятся. Источник истины — сессия
  sub-agent'а; анализатор берёт результат по её **session ID**.
- **Если ответ обрезан** (модель упёрлась в лимит) — Hermes покажет
  предупреждение «⚠️ ОТВЕТ ОБРЕЗАН»; тогда попроси поднять лимит и повторить.

## Для анализатора

Модуль-анализатор пользователя читает результат **по session ID sub-agent'а**
(его показывает Hermes). Формат ответа `ask.py` — один JSON-объект:

```json
{
  "model": "...", "prompt": "...",
  "response": "...",            // полный финальный ответ (не обрезан)
  "reasoning_content": "...",   // полный CoT thinking-моделей
  "finish_reason": "stop", "truncated": false, "usage": {}
}
```

Если `response` пуст — весь ответ в `reasoning_content` (это норма для
thinking-моделей). Оба поля отдаются целиком.

## Что под капотом (справочно, руками не нужно)

```bash
cd ${LAB_ROOT}/projects/redteam
python3 ask.py --file /tmp/case.txt                    # один кейс → полный ответ
python3 ask.py --file /tmp/case.txt --history hist.json # продолжение диалога
```

## Правила безопасности (жёстко)

- target ≠ attacker ≠ judge. Тестируемая модель — только target.
- Scope пустой по умолчанию; активные тесты — только своя / письменно
  авторизованная модель.
- Hermes передаёт промпт как есть, но сам не изобретает рабочие вредоносные
  payload (оружие/CBRN/malware).
- Ключи — только env / `~/.hermes/.env`, никогда в файлах пакета.
